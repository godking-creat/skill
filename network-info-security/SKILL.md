# 网络信息安全评估

## 概述

本技能提供网络信息安全评估的专业能力，以问答式咨询方式引导用户完成系统安全分析。覆盖 Web 应用、网络基础设施、移动应用和云环境四大领域，基于 OWASP Top 10、CWE 等业界标准框架，输出包含风险评级和修复建议的结构化安全评估报告。

## 触发场景

- 用户要求对某个系统/应用进行安全评估或安全检查
- 用户询问某类漏洞的风险和修复方案
- 用户需要安全加固建议或安全配置审查
- 用户需要生成安全评估报告
- 关键词：安全评估、漏洞扫描、安全检查、风险分析、安全加固、渗透测试、安全审计、网络安全

## 评估工作流

### 第 1 步：确定评估目标与范围

主动询问用户以下信息（按需选择，避免一次问太多）：

1. **目标系统名称**：评估对象的名称或标识
2. **系统类型**：从以下类型中选择
   - `web` — Web 应用（网站、API 服务、SaaS 平台）
   - `network` — 网络基础设施（防火墙、交换机、VPN、网络架构）
   - `mobile` — 移动应用（iOS/Android App）
   - `cloud` — 云环境（AWS/阿里云/腾讯云等云上架构）
   - `general` — 通用系统（不确定类型或混合环境）
3. **评估范围**：哪些组件在范围内、哪些在范围外
4. **已有信息**：用户是否已有渗透测试报告、扫描结果、架构图等

> 示例提问："请描述一下您要评估的系统——是 Web 应用、网络基础设施、移动应用还是云环境？主要关注哪些方面的安全？"

### 第 2 步：加载评估框架

根据系统类型，加载对应的参考文档：

- 加载 `references/security-assessment-framework.md` 获取该系统类型的安全评估维度和检查项
- 加载 `references/security-checklist.md` 获取逐项检查清单

按文档中的检查维度逐类分析。对于每个维度，根据用户提供的信息或系统描述判断是否存在风险。

### 第 3 步：交互式安全咨询

以问答方式逐步推进评估。每个轮次聚焦 1-2 个安全维度，向用户提出具体问题。

**咨询原则**：
- 一次只问 1-3 个相关问题，避免信息过载
- 问题要具体可答，给出选项或示例
- 根据用户回答实时给出初步风险评估
- 对用户不确定的项目，标记为"待确认"并继续推进

**示例对话**：
```
问：您的 Web 应用是否使用了 HTTPS？TLS 版本是多少？
答：用了 HTTPS，但不确定 TLS 版本。
→ 标记为待确认，提示用户可通过 nmap 或 SSL Labs 检测。
→ 如果确认 TLS 1.0/1.1 仍在使用，记录为中等风险。
```

### 第 4 步：风险评级

对每个识别到的安全问题，加载 `references/risk-rating-matrix.md`，按三个维度评级：

1. **影响程度** (1-5)：问题被利用后造成的损害程度
2. **利用难度** (1-5)：攻击者利用该问题的难易程度
3. **影响范围** (1-5)：问题波及的用户和系统范围

三维总分 (3-15) 对应五个风险等级：严重 / 高 / 中 / 低 / 信息。

**评级原则**：
- 基于实际可利用性而非理论可能性
- 考虑当前系统的具体上下文（暴露面、防护措施等）
- 对不确定的因素取保守估计

### 第 5 步：生成评估报告

评估完成后，使用 `scripts/generate_security_report.py` 生成结构化报告。

**方式一：交互式生成**

直接运行脚本，按提示输入评估结果：
```bash
python scripts/generate_security_report.py
```

**方式二：通过 JSON 数据生成**

将发现整理为 JSON 文件后批量生成：
```bash
python scripts/generate_security_report.py --target "目标系统" --type web --findings findings.json --output report.md
```

JSON 文件格式：
```json
[
  {
    "title": "TLS 版本过低",
    "description": "服务器仍支持 TLS 1.0/1.1，存在 BEAST/POODLE 等降级攻击风险",
    "evidence": "nmap --script ssl-enum-ciphers 结果显示 TLS 1.0 启用",
    "impact": 3,
    "exploitability": 4,
    "scope": 4,
    "recommendation": "禁用 TLS 1.0/1.1，仅保留 TLS 1.2+，配置 HSTS 头",
    "references": "https://owasp.org/Top10/A02_2021-Cryptographic_Failures/"
  }
]
```

> 脚本会自动计算风险等级和总分。impact/exploitability/scope 各为 1-5 的整数。

### 第 6 步：提供修复建议

为每个风险项提供：
1. **即时修复方案**：具体的技术配置或代码修改建议
2. **临时缓解措施**：在完整修复前的过渡方案
3. **长期改进建议**：流程和架构层面的改进

## 参考资源

### references/security-assessment-framework.md
安全评估框架文档，包含四大系统类型的详细评估维度。评估时根据目标系统类型加载对应章节。覆盖 OWASP Top 10、网络边界安全、移动应用安全和云安全等标准。

### references/security-checklist.md
分系统类型的安全检查清单。评估时逐项确认，支持快速识别遗漏的安全控制。包含 Web 应用、网络基础设施、云环境和通用安全检查项。

### references/risk-rating-matrix.md
风险评级矩阵，定义影响程度、利用难度、影响范围三个维度的评分标准和综合风险等级计算方法。包含修复优先级建议。

### scripts/generate_security_report.py
安全评估报告生成脚本。支持交互式输入和 JSON 批量导入两种模式，自动计算风险等级，输出标准化的 Markdown 格式报告。

## 输出规范

生成的安全评估报告应包含以下部分：

1. **评估摘要表**：目标、类型、人员、时间、发现总数
2. **风险概览**：各风险等级的数量分布
3. **详细发现**：按风险等级从高到低排序，每项包含描述、证据、评级、修复建议
4. **总结建议**：短期行动项和长期改进方向

## 注意事项

- 本技能提供的安全评估基于用户描述和已知信息，不等同于专业渗透测试
- 对于严重风险，建议用户聘请专业安全团队进行深度验证
- 评估结果应作为安全改进的参考，不作为合规认证的依据
- 始终遵循负责任披露原则，不提供具体攻击利用代码
